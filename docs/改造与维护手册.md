## 1. Android 版本兼容范围

### 当前结论

- **minSdkVersion = 21** → Android 5.0
- **targetSdkVersion = 23** → Android 6.0 行为
- **实机验证：Android 17 / API 37 / 澎湃OS4 / KernelSU**
- 在“改动不多”的前提下，合理范围是：
  - **Android 5.0 – Android 17**
  - API 21 – 37
  - 共 **13 个大版本**

### 无 root 分支（原版逻辑）

`BridgeFS` 内置：

```java
LOCAL_MODE = Build.VERSION.SDK_INT <= 29;   // Android 10 及以下
```

- **Android 5.0 – 10（API21–29）**：直接走原版 `java.io.File` / `BitmapFactory` 逻辑，
  不启动 `su`，完全不需要 root。
- **Android 11+（API30+）**：走 BridgeFS/root 桥；桥不可用时每个方法自动回退普通 File API。
- 因此：
  - 老 Android + 老微信（数据在 `/sdcard/tencent/MicroMsg`）→ 原版逻辑，无 root。
  - 新 Android + 新微信（数据在 `/data/data`）→ root 桥。
  - 旧版 APK 的“导出/清理/看图”在没有 root 的老系统上仍按原版工作。

### 微信版本兼容

- 重点兼容 **微信 8.0.x**（当前服务器仍允许登录的版本段）。
- 清理/扫描同时识别两套布局：
  - 老外部布局：`tencent/MicroMsg/<hash>/{image2,video,voice2,favorite,avatar,sns,sfs,image,music}`
  - 新 8.x 内部布局：`/data/data/com.tencent.mm/MicroMsg/<hash>/...`
  - 新版外部缓存：`Android/data/com.tencent.mm/cache`（由 `wechat8_cache_links.sh` 映射）
- 7.x 及更老版本服务器大多已拒绝登录，不专门适配；若某设备仍能登录，原版外部路径会走回退逻辑，但未验证。
- `favorite/` 是用户收藏数据，永久排除在清理删除之外。

### 为什么下限是 21

代码用到了：

- `MediaCodec.getOutputImage` / `android.media.Image`（API 19）
- `MediaCodec` / `MediaFormat.KEY_MAX_INPUT_SIZE`（API 16）
- Java 8 字节码由 d8 处理
- 桥依赖 Android 的 toybox：
  - `find -L`
  - `stat -L`
  - `xargs -0 -r`
  - `rmdir`

Android 5.0 以下 toybox/命令行为不稳定，且 root 方案也不现实，因此不建议再降。

### 为什么上限写 17

- APK 的 targetSdk 仍是 23，Android 14+ 安装时必须加：
  ```bash
  adb install -r -g --bypass-low-target-sdk-block ...
  ```
- 已实机验证 Android 17；Android 18+ 未验证。
- 目标设备必须已有 root（KernelSU/Magisk），否则桥无法工作。
- 原生库已删除、native 方法已有 Java 桩；当前在 arm64 设备验证通过。

### 如果强行继续兼容

- 想下探到 Android 4.4（API 19）：
  - 需要把 minSdk 改 19
  - 重新验证 toybox 的 `find -L/stat -L/xargs -r`
  - 重新验证 MediaCodec 输出 Image
  - 不推荐，属于额外工作量。
- Android 18+：
  - 需要重新验证 `su`、FUSE、`--bypass-low-target-sdk-block` 是否仍可用。

## 2. 最短重建路径（已有 `apktool_out` 工程）

以后只改 BridgeFS 或资源时，用这一条路径，不用从原始 APK 反编译。

```bash
cd ~/tools/wx_assist
source tools/env.sh

# 1) 编译 BridgeFS -> dex -> apktool 打包 -> 注入 classes2.dex -> 签名
tools/build_apk.sh --clean

# 进入工程目录（产物/脚本都集中在这里）
cd ~/tools/wx_assist/workspace

# 2) 推桥脚本（改了 wxbridge.sh 时必须做）
adb push bridge/wxbridge.sh /data/local/tmp/wxbridge.sh
adb shell chmod 666 /data/local/tmp/wxbridge.sh

# 3) 安装（同签名覆盖，不丢数据/uid）
adb install -r -g --bypass-low-target-sdk-block \
    bridge/signed/bridge-p0-inj-aligned-signed.apk

# 4) 把新产物拷回交付目录
cp -f bridge/signed/bridge-p0-inj-aligned-signed.apk \
      /home/ted/Projects/wx_assist/微信助手-改造版.apk
```

`tools/build_apk.sh` 做的事：

1. `ecj` 编译 `bridge/src/.../BridgeFS.java`（android.jar 作为 bootclasspath）
2. `d8` 转 dex
3. `apktool b apktool_out` 重打包
4. Python 注入 `classes2.dex`（multidex）
5. `uber-apk-signer` 做 zipalign + v1/v2/v3 签名
6. 自动把上一版保存为 `bridge/signed/bridge-p0-prev.apk`

> APK 内含 zip 时间戳，所以每次重建 SHA-256 会变化；当前交付包哈希见 §0，重建后以新哈希为准，功能一致。

## 4. 代码改动清单（最不绕弯子的版本）

### 4.1 BridgeFS 客户端

文件：`~/tools/wx_assist/workspace/bridge/src/com/wandoujia/ymir/bridge/BridgeFS.java`

职责：

- 启动 root 桥：`/system/bin/su -c sh /data/local/tmp/wxbridge.sh`
- 协议：`PING / LIST / TREE / READ / DELETE`
- 路径归一：`/data/media/0/X` ↔ `/storage/emulated/0/X`
- 缓存：
  - `TYPE`: path → 目录/文件
  - `META`: path → {size, mtime}
  - `CHILDREN`: dir → 直接子项
  - `TREES`: 已完成整树预取的根
- 首扫用 `TREE` 一次拉全量，避免 3.7 万目录逐次 LIST
- 空目录也预建空列表（否则会重复 LIST）
- `lastModified()` 返回毫秒：`stat %Y` 秒 × 1000
- `deleteTree()` 递归删除，供清理页使用
- `decodeFile()`：
  - 普通 JPEG/PNG：`BitmapFactory`
  - `wxgf`（微信 HEVC 裸流）：
    1. 找 Annex-B 起始码
    2. 解析 HEVC SPS 得到宽高
    3. 提取 VPS/SPS/PPS 作为 `csd-0`
    4. `MediaCodec` 解码 `video/hevc`（不接 Surface，直接 `getOutputImage`）
    5. YUV420 → NV21 → JPEG → Bitmap

### 4.2 自动 smali 手术：`bridge/patch_scan.py`

只做三类事：

| 类别 | 位置 | 改法 |
|---|---|---|
| 解码 | `android/support/v4/app/d.smali` | `BitmapFactory.decodeFile` → `BridgeFS.decodeFile` |
| 危险 File 调用 | `manager/{d,TrashScanner,MmConfig,ab,n,k,m,a}.smali` | `invoke-virtual File->M` → `invoke-static BridgeFS->M(File,...)` |
| 大小 helper | `manager/d.smali` | `d.a(File)J` → `BridgeFS.length(File)J` |

运行后必须校验 `RESIDUAL_ISSUES: 0`。

### 4.3 手工 smali 补丁

#### A. 清理递归删除

文件：`apktool_out/smali/android/support/v4/app/d.smali`
方法：`a(Ljava/lang/String;Ljava/io/FilenameFilter;)V`

在该方法入口插入：

```smali
new-instance v0, Ljava/io/File;
invoke-direct {v0, p0}, Ljava/io/File;-><init>(Ljava/lang/String;)V
invoke-static {v0, p1}, Lcom/wandoujia/ymir/bridge/BridgeFS;->deleteTree(Ljava/io/File;Ljava/io/FilenameFilter;)Z
return-void
```

#### B. 收藏夹从清理中排除

文件：`apktool_out/smali/com/wandoujia/ymir/manager/TrashScanner.smali`

1. 构造器里把 `o`（FAV_CACHE）默认值改为 `0`：
   ```smali
   .line 54
   const/4 v0, 0x0
   iput-boolean v0, p0, Lcom/wandoujia/ymir/manager/TrashScanner;->o:Z
   ```
2. `g()J` 直接返回 0，避免“收藏夹大小”计入清理总量：
   ```smali
   .method public final g()J
       .locals 2
       .prologue
       const-wide/16 v0, 0x0
       return-wide v0
   .end method
   ```

> 原因：`favorite/` 是用户收藏数据，不是缓存，不能当垃圾删。

## 5. 桥协议与 root 侧脚本

文件：`~/tools/wx_assist/workspace/bridge/wxbridge.sh`

命令：

| 命令 | 返回 |
|---|---|
| `PING` | `OK PONG` |
| `LIST <dir>` | 单层条目，`类型\t大小\tmtime\t路径`，最后 `END` |
| `TREE <dir>` | 递归整棵子树（含起点），最后 `END` |
| `READ <file>` | `DATA <n>\n` + 精确 n 字节 |
| `DELETE <path>` | 文件 `rm -f`；空目录 `rmdir`；否则 `ERR` |

必须使用：

```sh
find -L "$1" -mindepth ... -print0 | xargs -0 -r stat -L -c '%F\t%s\t%Y\t%n'
```

三个关键点：

1. **必须 `find -L` + `stat -L`**：P3 后 `image2/video/...` 是 symlink，少一个 `-L` 就会识别错。
2. **不能用 `find ... -exec stat {} +`**：toybox 在大目录树会漏条目（image2 54257 项只返回 14744）。
3. **格式串必须是真实 TAB 字节**：toybox `stat` 不解析 `\t` 转义。

## 7. 清理删除链

路径：

```text
CleanFragment -> TrashScanner.b() -> z.run()
  -> android.support.v4.app.d.c(String)
  -> d.a(String, FilenameFilter)
  -> BridgeFS.deleteTree(File, FilenameFilter)
  -> BridgeFS.delete(File)
  -> bridge DELETE
```

特点：

- 文件：桥 `rm -f`
- 空目录：桥 `rmdir`
- 非空目录：App 先递归子项，再删空目录
- 非桥路径（App 自有目录）：自动回退普通 `File.delete()`
- 收藏夹不参与删除

**注意**：实际点“清理”会删除约 798MB 缓存，执行前确认。

## 9. 最容易踩的坑（按优先级）

1. `listFiles` 解析行时 TAB 数错 → 所有条目被丢弃 → 计数 0。
2. 每目录一次 LIST → 3.7 万次进程往返 → 数分钟；必须 TREE 预取。
3. 空目录没有 CHILDREN key → 仍会 LIST；必须预建空列表。
4. toybox `find -exec {} +` 漏条目 → 必须 `find -print0 | xargs -0 -r stat`。
5. P3 symlink 后 `stat` 不跟随 → 必须 `find -L` + `stat -L`。
6. `stat %Y` 是秒，`File.lastModified()` 是毫秒 → 必须 `×1000`。
7. wxgf 是 HEVC 裸流，`BitmapFactory` 解不了 → MediaCodec + SPS 解析。
8. MediaCodec 用 ImageReader Surface 在该机型会拿到无效 plane（JNI abort）→ 改成不接 Surface，直接 `getOutputImage`。
9. `favorite/` 是用户收藏，不是缓存 → 不能清理。
10. Android 14+ 安装 targetSdk23 必须 `--bypass-low-target-sdk-block`。
11. `su` 只对已授权 uid 可见；重装 uid 变化后要在 KernelSU 重新授权。
12. `/data/local/tmp` 下脚本要让 App 能执行，权限一般 `666`。
13. 屏幕会自动锁，UI 测试前先 `KEYCODE_WAKEUP`。
